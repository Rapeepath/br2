# Servo — แค็ตตาล็อกหุ่นยนต์ฮิวแมนนอยด์

เว็บโชว์รูม (React + Vite + TypeScript) ดีไซน์แบบเว็บผู้ผลิตรถยนต์ นำเสนอหุ่นยนต์ฮิวแมนนอยด์ที่ผู้ซื้อในไทยสั่งซื้อได้จริง
ครบทั้งราคาทุกรุ่นย่อย สเปกการเคลื่อนไหว แบตเตอรี่ ระบบประมวลผล เซนเซอร์ ซอฟต์แวร์ การรับประกัน ช่องทางจำหน่ายในไทย
และคู่มือก่อนซื้อ ข้อมูลทั้งหมดมาจากการค้นคว้าแบบ deep research จากเว็บไซต์ผู้ผลิต ผู้จัดจำหน่ายในไทย และสื่อเทคโนโลยี พร้อมแหล่งอ้างอิง

เป็นเว็บพี่น้องของ `../1` (Maew แค็ตตาล็อกสายพันธุ์แมว) ใช้โครงสร้างเดียวกัน แต่เปลี่ยนสินค้าและธีม
(เดิมโฟลเดอร์นี้เป็นเว็บรถยนต์ไฟฟ้า "Watt" สำรองไว้ที่ `../_backup/2-watt-ev-2026-10-26.tgz`)

## เริ่มใช้งาน

``bash
npm install
npm run dev        # เว็บ http://localhost:5174   หลังร้าน http://localhost:5174/admin
``

เว็บนี้ใช้พอร์ต 5174/4174 (เว็บ Maew ใน `../1` ใช้ 5173/4173) จึงเปิดทั้งสองเว็บพร้อมกันได้

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | เปิดเซิร์ฟเวอร์พัฒนา (เว็บ + `/admin` + API ของ POS ในพอร์ตเดียว) |
| `npm run build` | ตรวจ type แล้ว build ไปที่ `dist/` (หน้าเว็บ `dist/index.html` และหลังร้าน `dist/admin/index.html`) |
| `npm run preview` | เสิร์ฟ `dist/` พร้อม API ที่ http://localhost:4174 |
| `npm run server` | เซิร์ฟเวอร์แยกไม่ต้องใช้ Vite: เสิร์ฟ `dist/` + API ที่ http://localhost:3002 (รัน `npm run build` ก่อน; เปลี่ยนพอร์ตด้วย `PORT`) |
| `npm run pos:reset` | ล้างฐานข้อมูลจำลอง แล้วสร้างการขายย้อนหลัง 60 วันชุดใหม่ที่จบที่วันนี้ |
| `npm run data` | สร้าง `src/data/*.json` ใหม่จาก `research_notes/` แปลงราคา และดาวน์โหลดภาพ (`-- --force` เพื่อโหลดภาพใหม่ทั้งหมด) |
| `npm test` | unit + component tests (Vitest + Testing Library) |
| `npm run test:e2e` | end-to-end (Playwright ใช้ Chrome ในเครื่อง) — desktop และ mobile, ธีมสว่าง/มืด, สแกน axe, ภาพหน้าจอที่ `e2e/screenshots/` |
| `npm run test:all` | typecheck → unit → build → e2e |

## ข้อมูลในเว็บ

- **รุ่นในแค็ตตาล็อก:** หุ่นยนต์ฮิวแมนนอยด์ (เดินสองขา หรือร่างกายท่อนบนบนฐานล้อ) ที่สั่งซื้อหรือสั่งจองได้จากไทย ณ เดือนตุลาคม 2569
  มีราคาประกาศ และมีภาพถ่ายตามสัญญาอนุญาตเสรีของรุ่นนั้นจริง เรียงตามอันดับยอดส่งมอบของผู้ผลิต (Omdia ปี 2568) แล้วตามราคาเริ่มต้น
  ดูรายชื่อได้ที่ `src/data/models.json`
- **ราคา:** ราคาบาทที่ตัวแทนจำหน่ายในไทยประกาศ (เงื่อนไขภาษีตามประกาศของแต่ละราย) มิฉะนั้นแปลงจากราคาผู้ผลิต (USD/CNY/EUR)
  ด้วยอัตราขายถัวเฉลี่ยของ ธปท. ใน `market.json` ปัดเป็นหลักร้อยบาท และแสดงว่า "ประมาณ" — ยังไม่รวมค่าขนส่ง อากร และภาษีมูลค่าเพิ่ม
- **สเปก:** ตามหน้าสินค้าและเอกสารของผู้ผลิตเป็นหลัก ค่าที่ไม่เปิดเผยแสดงเป็น "ไม่ระบุ" ไม่ประมาณเอง
- **ตลาดและคู่มือ:** ยอดส่งมอบรายผู้ผลิต อัตราแลกเปลี่ยน ผู้จำหน่ายในไทย ภาษีนำเข้า ค่าไฟ ค่าใช้จ่าย และข้อกฎหมาย อยู่ใน `research_notes/หุ่นยนต์ฮิวแมนนอยด์/data/market.json`
- **บันทึกการค้นคว้า:** `research_notes/หุ่นยนต์ฮิวแมนนอยด์/*.md` และรูปแบบข้อมูลใน `SCHEMA.md`

## หน้าในเว็บ

- **หุ่นยนต์** (`/`) — เวทีโชว์รูมเลือกรุ่น (แถบรุ่น เส้นสแกน LED ตัวเลขสเปกนับขึ้น) ตัวเลขภาพรวมแค็ตตาล็อก ค้นหา/กรอง (ประเภทการใช้งาน ยี่ห้อ ช่วงราคาเริ่มต้น) และเรียงลำดับ (ราคา องศาอิสระ น้ำหนักบรรทุก เวลาใช้งาน) ตัวกรองเก็บใน URL
- **รายละเอียดรุ่น** (`/models/:id`) — แผ่นสเปกสินค้า: ราคาและที่มาของราคา, แถบสเปกหลัก และแท็บ 5 แท็บ
  - ภาพรวม (ความเป็นมา จุดเด่น งานที่ใช้)
  - รุ่นย่อยและราคา
  - ขนาดและระบบ (ภาพเทียบความสูงกับผู้ใหญ่ 170 ซม. เซนเซอร์ ซอฟต์แวร์ การชาร์จ)
  - ความปลอดภัยและการรับประกัน
  - ก่อนตัดสินใจ (ข้อดี ข้อจำกัด การจำหน่ายในไทย)
- **เปรียบเทียบ** (`/compare`) — แผ่นเทียบสเปกสูงสุด 3 รุ่น 8 หมวด มีสี่เหลี่ยมสีเข้มบอกค่าที่เด่นที่สุด
- **คู่มือก่อนซื้อ** (`/guide`) — ภาพรวมตลาด, เช็กลิสต์, การเตรียมพื้นที่, ช่องทางซื้อในไทย, ค่าไฟต่อการชาร์จ, ค่าใช้จ่าย, กราฟช่วงราคา (แกนลอการิทึม), มาตรการรัฐและกฎหมาย
- **แหล่งข้อมูล** (`/sources`) — วิธีรวบรวมข้อมูล, อันดับยอดส่งมอบของผู้ผลิต, แหล่งอ้างอิงรายรุ่น, แหล่งข้อมูลตลาด และเครดิตภาพ

## หลังร้านและเครื่องขายหน้าร้าน (POS จำลอง) — `/admin`

เปิด http://localhost:5174/admin (`npm run dev`) หรือ http://localhost:3002/admin (`npm run build && npm run server`)
แล้วเลือกพนักงานและใส่รหัส PIN ทดลอง

| พนักงาน | สิทธิ์ | PIN |
|---|---|---|
| กฤษดา วัฒนกุล (ผู้จัดการโชว์รูม) | ผู้จัดการ | 1111 |
| อรอนงค์ ศรีประเสริฐ (ที่ปรึกษาการขาย) | พนักงาน | 2222 |
| ภัทรพล เกียรติศักดิ์ (วิศวกรบริการ) | พนักงาน | 3333 |

- **ภาพรวม** ยอดขายวันนี้เทียบเมื่อวานช่วงเวลาเดียวกัน ตัวเลข 30 วัน กราฟรายวัน สินค้าขายดี ช่องทางชำระ หมวดสินค้า สินค้าใกล้หมด บิลล่าสุด กะปัจจุบัน
- **ขายหน้าร้าน** เลือกสินค้า (หุ่นยนต์ทุกรุ่นย่อย อุปกรณ์เสริม บริการ) ส่วนลดรายการและท้ายบิล (บาทหรือ %) เลือกหรือเพิ่มลูกค้า
  ชำระด้วยเงินสด (คำนวณเงินทอน) พร้อมเพย์ (QR จำลอง) บัตร หรือโอน แล้วออกใบเสร็จ/ใบกำกับภาษีอย่างย่อ
  หรือใบกำกับภาษีเต็มรูปเมื่อผู้ซื้อเป็นนิติบุคคล พิมพ์ได้เฉพาะใบเสร็จ ราคา ส่วนลด VAT 7% (รวมในราคา) และสต็อกคำนวณที่เซิร์ฟเวอร์ทุกครั้ง
- **รายการขาย** กรองตามช่วงวัน สถานะ ช่องทางชำระ พนักงาน ค้นหาเลขบิล/ลูกค้า/สินค้า ดูบิล พิมพ์ซ้ำ และคืนเงิน
  (พนักงานต้องใส่ PIN ผู้จัดการ สินค้ากลับเข้าสต็อก)
- **สินค้าและสต็อก** ราคา ต้นทุน อัตรากำไร สต็อก ยอดขาย หน้าสินค้ามีข้อมูลรุ่นครบจากแค็ตตาล็อก (ทุกรุ่นย่อย สเปก เซนเซอร์ ซอฟต์แวร์
  การรับประกัน ข้อดีข้อเสีย แหล่งข้อมูล) ผู้จัดการแก้ราคา/ต้นทุน/จุดสั่งซื้อ/เปิดปิดการขายได้ รับสินค้าเข้า นับและปรับยอดสต็อก บัตรสต็อกพร้อมยอดคงเหลือ
- **ลูกค้า** บุคคลและนิติบุคคล (เลขผู้เสียภาษี ที่อยู่ออกใบกำกับ) ยอดซื้อสะสม ประวัติการซื้อ
- **กะและเงินสด** เปิดกะด้วยเงินทอนตั้งต้น นำเงินเข้า/ออกลิ้นชัก ปิดกะโดยนับเงินเทียบยอดที่ควรมี (แสดงเงินขาด/เกินทันที) ประวัติทุกกะ
- **รายงาน** ช่วงวันที่ใดก็ได้ ยอดขาย กำไรขั้นต้น VAT ส่วนลด คืนเงิน กราฟรายวันและรายชั่วโมง แยกตามสินค้า หมวด ช่องทาง พนักงาน ส่งออกบิลเป็น CSV
- **บันทึกกิจกรรม** ทุกการกระทำ (เข้าสู่ระบบ ขาย คืนเงิน สต็อก ราคา ลูกค้า กะ ตั้งค่า) **ตั้งค่า** ข้อมูลร้านบนใบเสร็จ พนักงานและสิทธิ์ และปุ่มสร้างข้อมูลจำลองใหม่

**สิ่งที่จำลอง:** ไม่มีการรับหรือตัดเงินจริงทุกช่องทาง (QR บัตร และบัญชีรับโอนเป็นของสมมติ) ใบเสร็จระบุว่าเป็นเอกสารจากระบบจำลอง
ลูกค้า พนักงาน เลขผู้เสียภาษี และยอดขายย้อนหลัง 60 วันสร้างขึ้นเอง (ผ่านกติกาเดียวกับหน้าร้าน จึงตัวเลขทุกหน้าตรงกัน)
ส่วนสินค้าและราคามาจากข้อมูลจริงในแค็ตตาล็อก ฐานข้อมูลเป็นไฟล์ JSON ที่ `.pos-data/db.json` (สร้างอัตโนมัติเมื่อเปิดครั้งแรก
เปลี่ยนที่อยู่ได้ด้วยตัวแปร `POS_DB`) e2e ใช้ไฟล์แยก `.pos-data/e2e.json` ที่สร้างใหม่ทุกครั้งที่เปิดเซิร์ฟเวอร์ทดสอบ

## เว็บไซต์ร้านเต็มรูปแบบ

### ส่วนที่ใช้ร่วมกันทั้งสองเว็บ (เพิ่มเมื่อ 6 พ.ย. 2569)

- **URL ปกติ + SEO:** ใช้ BrowserRouter (ลิงก์เก่าแบบ `#/x` จะเปลี่ยนเป็น `/x` ให้เอง) `npm run build` สร้างหน้า HTML สำเร็จรูปทุกหน้า
  ทั้งภาษาไทยและอังกฤษ (`scripts/prerender.mjs` + `src/entry-server.tsx`) พร้อม title, description, canonical, hreflang,
  Open Graph/Twitter, JSON-LD (Store, Product, BreadcrumbList, FAQPage), `sitemap.xml` และ `robots.txt` (กัน `/admin` และ `/api`)
  ทะเบียนหน้าทั้งหมดอยู่ที่ `src/routes.tsx` และตั้งโดเมนจริงด้วยตัวแปร `SITE_URL`
- **ภาษาอังกฤษ:** ทุกหน้ามีคู่ภาษาอังกฤษใต้ `/en/…` (สลับภาษาได้จาก header) ข้อความหน้าจอใช้ `src/i18n/` และ copy ราย
  หน้า ส่วนข้อมูลสินค้าอยู่ที่ `src/data/en.json` ซึ่ง `npm run data` สร้างจาก `research_notes/<หัวข้อ>/i18n/en/*.json`
- **ข้อมูลสดจากหลังร้าน:** หน้าเว็บดึงราคาและสต็อกจาก `/api/public/catalog` และข้อมูลร้านจาก `/api/public/store`
  (`src/lib/live.ts`) ถ้าเปิดแบบไฟล์ static ที่ไม่มี API จะแสดงข้อมูลจากแค็ตตาล็อกแทน
- **ติดต่อและนัดหมาย:** หน้า `/contact` (ฟอร์มสอบถาม, โทร, LINE, แผนที่, เวลาเปิด), `/booking` (เลือกวันและช่องเวลาจาก
  เวลาเปิดร้าน ดาวน์โหลด .ics ได้), ปุ่ม LINE/โทรลอยบนมือถือ และข้อมูลร้านใน footer ทุกฟอร์มส่งเข้า "ลูกค้าที่สนใจ" ใน `/admin`
- **FAQ และ PDPA:** `/faq` (มี FAQPage JSON-LD) และ `/privacy` (นโยบาย + ฟอร์มขอดู/ลบ/แก้ข้อมูล) ทุกฟอร์มต้องติ๊กยินยอม
  มีช่องกันบอท และจำกัด 20 ครั้งต่อ 10 นาทีต่อ IP (`POS_RATE_LIMIT`) เชื่อ `X-Forwarded-For` เฉพาะเมื่อตั้ง `POS_TRUST_PROXY=1`
  (ใช้เมื่อวางหลัง reverse proxy) ผู้จัดการลบข้อมูลส่วนบุคคลของลูกค้ารายใดก็ได้จากหน้าลูกค้าที่สนใจ
- **แกลเลอรีและรีวิว:** ภาพเพิ่มจาก Wikimedia Commons (`public/images/gallery/`, เครดิตในหน้าแหล่งข้อมูล) วิดีโอเล่นเมื่อกด
  เท่านั้น รีวิวจากผู้ชมเว็บต้องรอผู้จัดการอนุมัติใน `/admin` ก่อนแสดง ไม่มีรีวิวจำลองใดๆ
- **รูปภาพ:** `npm run images` (sharp) สร้าง AVIF/WebP ขนาด 480/960/1600 ที่ `public/images/r/` ให้คอมโพเนนต์ `<Picture>`
  (build เรียกให้อัตโนมัติ)
- **หลังร้านเพิ่ม:** ลูกค้าที่สนใจ (สถานะ ผู้ดูแล บันทึก ลบข้อมูลตาม PDPA), นัดหมาย (ปฏิทินรายสัปดาห์), รีวิว (อนุมัติ/ซ่อน),
  ตั้งค่าอีเมล LINE แผนที่ และเวลาเปิดร้าน ภาพรวมมีตัวเลขลูกค้าจากเว็บ เมนูมีตัวเลขรายการใหม่
- **ทดสอบ:** `e2e/site.spec.ts` (หน้าเดิม), `e2e/site-en.spec.ts` (ภาษาอังกฤษ แกลเลอรี รีวิว), `e2e/site-commerce.spec.ts`
  (หน้าใหม่และฟอร์ม), `e2e/admin.spec.ts` ถ้าจะรันสองชุดพร้อมกันให้ใช้ `PW_PORT` และ `PW_DIST` แยกพอร์ตและโฟลเดอร์ build
- **สิ่งที่จำลอง:** ชื่อร้าน ที่อยู่ เบอร์โทร LINE สต็อก การจอง และการชำระเงินเป็นระบบสาธิต (ท้ายเว็บแจ้งไว้) ไม่มีการรับเงินจริง

## Deploy บน Vercel

Import repo นี้ใน Vercel ได้เลย ไม่ต้องตั้งค่าเพิ่ม เพราะ `vercel.json` สั่ง build ด้วย `npm run build:vercel`
(`npm run build` แล้วตามด้วย `scripts/vercel-output.mjs`) ซึ่งเขียนโฟลเดอร์ `.vercel/output` ตาม Build Output API
หน้าเว็บที่ build แล้วขึ้น CDN ส่วน `/api/*` รวมถึงหน้าที่ CDN ไม่มีไฟล์ เช่นหน้า 404 จะวิ่งไป function ตัวเดียว
คือ `server/vercel.ts` ซึ่งเรียก API ชุดเดียวกับ `npm run server`

- **ฐานข้อมูล:** ใน Vercel ไปที่ Storage → Create Database → **Upstash for Redis** แล้วเชื่อมกับโปรเจกต์นี้
  (ระบบจะใส่ `KV_REST_API_URL` และ `KV_REST_API_TOKEN` ให้เอง) จากนั้น Redeploy หนึ่งครั้ง
  ฐานข้อมูลทั้งก้อนเก็บไว้ที่ key `<ชื่อ package>:db` จึงใช้ Redis ก้อนเดียวร่วมกันทั้งสองเว็บได้
  ถ้าไม่เชื่อม Redis หลังร้านก็ยังเปิดได้ แต่แต่ละ instance จะเก็บข้อมูลไว้ใน `/tmp` ของตัวเอง
  ข้อมูลจะหายเมื่อ instance ปิด (หลังไม่มีคนใช้ไปสักพัก) และอาจถูกให้ล็อกอินใหม่
- **ตัวแปรอื่น:** `SITE_URL` = โดเมนจริง สำหรับ canonical และ sitemap (ตั้งใน Settings → Environment Variables)
- **ภูมิภาค:** ตั้ง Settings → Functions → Function Region เป็น Singapore (`sin1`) และสร้าง Redis ที่สิงคโปร์
  เพื่อให้ผู้ใช้ในไทยได้ response เร็ว
- ทดสอบในเครื่อง: `npm run build:vercel` แล้วดูผลใน `.vercel/output/` (โฟลเดอร์นี้อยู่ใน .gitignore)
